Build the project

Add agentic, multi-step behavior — feature #3

Give your app a task that takes Claude more than one round trip to finish — a small tool-use loop, or light retrieval over your own data, whichever fits.

  1. Define the multi-step task in one sentence: what starts it, what "done" looks like.
  2. Implement the loop with a hard step limit so it can't run away.
  3. Watch it run at least twice and note one place it did something you didn't expect.
Claude fluency

Agent loops, and MCP if it fits

The reason/act/observe pattern behind agentic behavior, and where the Model Context Protocol fits if your project can use a real MCP server or tool.

Teach me the agent loop with my own task
I've built a loop where Claude does [describe the multi-step task from this week]. Explain the reason/act/observe pattern this maps to, why a step limit matters, and one real failure mode (infinite loop, tool misuse, runaway cost) I should guard against specifically for this task.
Should this be an MCP server?
Here's what my tool loop does: [describe it]. Would wrapping this as an MCP server make sense versus keeping it as an in-app function call? Give me the honest tradeoff, not just "yes, MCP is the future."
