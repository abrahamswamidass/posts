Name the Architecture

The sketch from last week becomes a real document, and Claude gets its first wire into the app. Small, deliberate scope: one ADR, one hello-world call.

Architecture

Write a real ADR for your stack

Take the target-state sketch from Week 1 and turn the biggest open decision — framework, hosting, data store, how Claude gets called — into a one-page Architecture Decision Record.

  1. State the decision in one sentence.
  2. List 2–3 alternatives you considered and why you rejected them.
  3. State the consequence you're accepting — what gets harder because of this choice.
  4. Save it as ADR-001 in the repo. This is the first of several.

Build the project

Scaffold the repo, make one real Claude call

Get the skeleton running: an empty UI shell — even a single blank page — wired to one live call to the Claude API. No feature logic yet, just proof the wire works end to end.

  1. Stand up the app shell in whatever framework ADR-001 chose.
  2. Make one real API call to Claude from that shell and render the raw response.
  3. Commit it. This is the ugliest, smallest possible version of "it's alive."
Claude fluency

Prompt engineering fundamentals

System prompts vs user turns, structured output, and the handful of prompting moves that matter more than any trick.

Then show me how to get reliable structured output (JSON matching a schema) from a Claude API call in [your language]. Use my project as the running example the whole way through.
