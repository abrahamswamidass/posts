Week 01

Kickoff & Commit

Before any code, decide what you're building and say so out loud. This is the smallest, cheapest week of the sprint on purpose — nothing here should be able to stop you from starting.

Architecture

Draw the shape of "before" and "after"

On one page — paper, Excalidraw, or a Claude-generated diagram — sketch two boxes-and-arrows pictures: the system as it exists today (even if "today" is nothing), and the system as you want it in week 12. Don't reach for accuracy; reach for a decision.

  1. List the 3–5 boxes involved (UI, API/Claude, data store, external source, deploy target).
  2. Draw one arrow per real interaction — no arrow you can't explain in one sentence.
  3. Under the "after" sketch, write one sentence: "Done, week 12, looks like: ___."

Build the project

Choose the project and write the brief

Pick the project (see the sprint hub for the default candidate — Pulse's dormant Phase 3 dashboard). Create the repo or branch, and write a single paragraph: what it does, who it's for, and why it counts as outside your comfort zone.

  1. Name the one thing that makes this uncomfortable — a UI you'll have to design, an audience you'll have to show it to, a stack you haven't touched.
  2. Create the repo/branch and a README with the one-paragraph brief.
  3. Do not write feature code yet — that starts Week 2.
Claude fluency

Learn how Claude Code's loop actually works

You already use Claude Code daily — this week, go one layer under "how" instead of "what." Understand the read-plan-edit-verify loop, how context and tools fit together, and where the model and the harness draw the line.

Build the mental model
Explain to me, as if I've used Claude Code daily but never thought about its internals, how a single turn actually works end to end: how my prompt becomes tool calls, how tool results come back into context, and where the agentic loop decides to keep going versus stop. Use a simple sequence diagram (Mermaid) with 4-5 steps. Then give me one sentence I could use to explain "what makes it agentic" to a colleague who's only used a chat-only LLM.
Pressure-test my project brief
Here is my one-paragraph project brief for a 12-week build: [paste your brief]. Act as a skeptical but constructive reviewer. Ask me 3 questions that would expose whether this project is actually small enough to demo in 12 weeks, and tell me directly if you think the scope needs to shrink.
Presentation & inhibition

Record yourself, alone, for 90 seconds

Rung 1 of 10

Open your phone or laptop camera. No script, no second takes. Explain your project out loud for 90 seconds: what it is, why it's uncomfortable for you, what week 12 looks like. Watch it back exactly once. Write down one filler word, hedge, or apology you want to drop by next week.

Done when
  • You can point to a one-paragraph brief and a repo for your project.
  • You've drawn a before/after sketch and written the one-sentence definition of done.
  • You understand, well enough to explain it, how a Claude Code turn moves from prompt to tool call to result.
  • You've recorded and watched your first 90-second pitch, and named one specific thing to change.
