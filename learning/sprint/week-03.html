Week 03

First Vertical Slice

The first feature, ugly and real. This is the week the project stops being a brief and starts being a thing you can point at and demo.

Architecture

Draw the data flow for feature #1

Before writing the feature, draw the actual path data takes: source → transform → Claude call → what the user sees. One arrow per hop, one line under each arrow saying what happens there.

  1. Identify the source of truth for this feature's input.
  2. Mark exactly where Claude enters the flow and what it's given.
  3. Mark where the output lands, and what happens if that step fails.
data flow diagram source / sink coupling failure path
Build the project

Ship the first vertical slice

One working screen, one real Claude-powered capability, start to finish. Styling can be ugly. Edge cases can be missing. It has to actually work once, for the happy path.

  1. Build the one screen/flow for feature #1.
  2. Wire it to the real Claude call from Week 2, now doing real work.
  3. Run it yourself, start to finish, without touching the code mid-run.
Claude fluency

Tool use / function calling

Give Claude a real tool to call — not just text in, text out.

Teach me tool use with my real feature
I want Claude to be able to call a real function as part of [describe feature #1] — for example [name a plausible tool, e.g. "look up an account balance" or "query a table"]. Walk me through defining a tool schema, handling the tool-call response, and returning the result back into the conversation, in [your language/SDK]. Show a complete, minimal working example I can adapt.
Debug my mental model
Here's the tool-use code I just wrote: [paste it]. Tell me, in plain terms, exactly what happens on each round trip between my code and the API when the tool gets called — I want to be able to explain this to someone else without hand-waving.
Presentation & inhibition

Demo it live to one trusted person

Rung 3 of 10

Five minutes, no slides, screen-share or in person. Show the vertical slice actually running. Ask exactly one question afterward: "What was confusing?" Write down their answer verbatim — don't argue with it.

Done when
  • Feature #1 works end to end on the happy path.
  • You can draw its data flow from memory.
  • You've implemented one real tool call and can explain the round trip.
  • You've demoed live to one person and captured their "what was confusing" answer.
