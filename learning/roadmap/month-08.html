Neural Nets, Embeddings & How LLMs Work

Core focus

Lift the hood, name the parts

You've spent seven months building the systems that feed models. Now you look inside one. The goal isn't to derive the math — it's to earn the right to speak about LLMs without hand-waving, so that when a stakeholder asks "how does it actually work," you answer with structure instead of vibes.

Neural networks, the honest short version

A single neuron is embarrassingly simple: take some inputs, multiply each by a weight, add them up, add a bias, then pass the result through a non-linear activation function (ReLU, sigmoid). That's it. Stack neurons side by side into a layer, stack layers front to back, and the whole thing becomes a very flexible function that maps inputs to outputs.

  • Training is just tuning the weights so the output is less wrong. You feed in an example, measure the error (the loss), and nudge every weight in the direction that shrinks it.
  • Gradient descent — the nudging rule. The gradient points uphill on the loss surface; you step the opposite way. Repeat millions of times and the loss rolls downhill toward a good-enough valley.
  • Backpropagation — the bookkeeping that makes it tractable. It's the chain rule applied backwards through the layers to figure out how much each weight contributed to the error, so you know which way to nudge each one.

Frame it this way and it stops being mystical: a neural net is a giant, flexible function, and training is curve-fitting at scale. Enough to speak fluently — not enough to write a paper, and that's the right amount for you right now.

Embeddings — the bridge concept

This is the month's keystone. An embedding turns a token — or a word, a sentence, a document — into a vector: a list of a few hundred to a few thousand numbers. The trick is that these vectors live in a space where meaning becomes geometry. Things that mean similar things land close together; things that don't sit far apart.

  • Vector space — every piece of text is a point. "Invoice" and "receipt" are neighbors; "invoice" and "giraffe" are across town.
  • Cosine similarity — how you measure "close." It's the cosine of the angle between two vectors: 1.0 means identical direction, 0 means unrelated, −1 means opposite. Direction, not distance, is what carries meaning here.

Internalize this one. It is the concept that connects your entire data career to AI: an embedding is just a feature vector where the features encode semantics. It's what makes semantic search, clustering, deduplication, and — next month — retrieval-augmented generation possible. If only one idea survives this month, make it this one.

Tokenization — the model's unit of thought

A model never sees characters or whole words. Text is first chopped into tokens — subword chunks. Common words are one token; rarer ones fracture into pieces ("tokenization" might become token + ization). This has real engineering consequences:

  • Cost and latency are billed and spent per token, not per word. A dense paragraph of code or JSON can cost far more tokens than the same length of English prose.
  • The context window is a hard budget measured in tokens — everything the model can "see" at once, prompt plus response. Blow the budget and the oldest content falls off the edge. You'll design around this constraint for the rest of the phase.
  • The same word can be one token or several depending on spacing and casing — which is why token counts surprise people who count words.

The transformer & attention

The transformer is the architecture under every modern LLM, and its heart is self-attention: a mechanism that lets each token look at every other token in the sequence and decide how much each one matters for interpreting it. "It" in a sentence can reach back and attend strongly to the noun it refers to.

  • Query / Key / Value — the intuition is a soft dictionary lookup. Each token emits a Query ("what am I looking for?"), every token offers a Key ("here's what I am"), and the match between query and keys decides how much of each token's Value gets mixed in. Not a hard hash lookup — a weighted blend.
  • Multi-head attention — run several of these lookups in parallel, each free to focus on a different kind of relationship (syntax, coreference, topic), then concatenate. More perspectives per layer.
  • Positional encoding — attention alone is order-blind (it's a set operation), so position information is added to each token's vector. That's how the model knows "dog bites man" differs from "man bites dog" without any recurrence.

Why transformers won where RNNs stalled: RNNs process tokens one at a time, sequentially, so they're slow to train and forget distant context. Attention looks at the whole sequence at once, in parallel — which maps beautifully onto GPUs and scales. Scaling is the whole story.

From next-token predictor to Claude

Here's the demystification in three moves. First, pre-training: the base model does exactly one thing — predict the next token — over a staggering amount of internet text. That alone teaches it grammar, facts, reasoning patterns, and style, but it's just an autocomplete; it doesn't yet know it's supposed to be helpful.

  • Fine-tuning / instruction tuning — further training on examples of instructions and good responses, so the model learns to follow directions rather than merely continue text.
  • RLHF / preference training — humans (and models) rank responses; the model is trained to prefer the ones people find helpful, honest, and harmless. This alignment step is what turns a raw predictor into an assistant you'd actually trust.
  • Inference controls — at generation time the model outputs logits (a raw score per possible next token), which a softmax turns into probabilities. Temperature flattens or sharpens that distribution (low = focused and deterministic, high = varied and creative); top-p (nucleus sampling) restricts choices to the smallest set of tokens whose probability sums to p.

Hold both truths at once: yes, it is "just predicting the next token" — and the instruction tuning plus preference training on top of that predictor is precisely what makes it useful. Neither half is the whole story.

Hands-on challenge
Build · ~7 hours

Make embeddings real — build a tiny semantic search over your own writing

Concepts stick when you can see them move. Take a corpus you actually care about — titles and paragraphs from your own GitHub posts — and turn abstract vectors into something you can query and plot.

  1. Embed a small corpus. Use an embeddings model (sentence-transformers locally, or an embeddings API) to turn each title/paragraph from your GitHub posts into a vector. Store the vectors alongside their source text.
  2. Build the search. Compute cosine similarity between a typed query's embedding and every item, then return the nearest few. That's a semantic search engine in about fifteen lines — no keyword matching anywhere.
  3. See the space. Reduce the vectors to 2D with t-SNE or UMAP and scatter-plot them. Watch related posts pull into visible clusters — meaning as geometry, on your screen.
  4. Inspect tokens. Tokenize a few passages and print the token count and the actual splits. Notice where words fracture, and how code or long words inflate the count against the context budget.
  5. Watch loss go down. Optionally, run a tiny neural net on a toy dataset (or a small MNIST notebook) and print the loss each epoch. Seeing the number fall is gradient descent made concrete.
Stretch — Embed two sentences that mean the same thing in different words ("The invoice is overdue" / "Payment on the bill is late") and show their high cosine similarity. Then embed an unrelated sentence and show the score collapse. That contrast is the intuition behind semantic search — prove it to yourself with numbers.

Terminology to own

Say these without hesitating

Embedding
Text turned into a vector where semantic similarity becomes geometric closeness.
Cosine similarity
The cosine of the angle between two vectors; 1 = same meaning, 0 = unrelated.
Token
The subword unit a model actually reads; not the same as a word.
Context window
The hard budget, in tokens, of everything the model can see at once — prompt plus output.
Self-attention
Each token weighs every other token to decide what's relevant to it.
Query/Key/Value
The three projections behind attention — a soft, weighted dictionary lookup.
Multi-head attention
Several attention lookups in parallel, each capturing a different relationship.
Positional encoding
Order information added to token vectors, since attention is otherwise order-blind.
Pre-training
Learning to predict the next token over vast text; produces the base model.
Fine-tuning
Further training on curated examples so the model follows instructions.
RLHF
Preference training on ranked responses to make the model helpful, honest, harmless.
Temperature
A knob that sharpens (low) or flattens (high) the next-token probability distribution.
Logits
The model's raw per-token scores, turned into probabilities by softmax.
